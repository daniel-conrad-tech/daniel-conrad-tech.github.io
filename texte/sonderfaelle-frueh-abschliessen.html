Geh schon mal vor.

Warum ein frühes Return den Ablauf klarer macht.

20. November 2026 KI In Zusammenarbeit mit KI erstellt; inhaltlich geprüft und redaktionell verantwortet von Daniel Conrad.
  • Softwaredesign
  • TypeScript
  • Lesbarkeit
  • Guard Clause
  • Early Return

Wenn ein Sonderfall erledigt ist, sollte der weitere Code ihn nicht mehr berücksichtigen müssen. Eine frühe Rückgabe kann genau das ausdrücken: Dieser Fall ist abgeschlossen. Für alles, was folgt, gilt eine klare Voraussetzung.

An einem kleinen Renderer für Antwortentwürfe lässt sich zeigen, warum das die Lesbarkeit verbessert – und wie daraus eine konkrete Regel für Coding-Agenten wird.

Diagnose

Ein Renderer erstellt den Text für einen Antwortentwurf. Unter die Antwort hängt er den ursprünglichen Nachrichtentext als Zitat. Ist dieser Text leer, besteht der Entwurf nur aus der Antwort.

export class ReplyDraftBodyRenderer {
    /** Appends the original plaintext as a line-by-line quote; preserves nesting. */
    render(response: ReplyBody, original: OriginalBody): DraftBody {
        const originalText = original.toString();
        const quote = originalText ? originalText.split("\n").map(line => `> ${line}`).join("\n") : "";
        return DraftBody.create(quote ? `${response.toString()}\n\n${quote}` : response.toString());
    }
}

Der Code ist kurz. Beim Lesen muss ich trotzdem zweimal eine Entscheidung nachvollziehen: Wird ein Zitat erzeugt? Und wird dieses Zitat an die Antwort angehängt?

Muster

Beide Entscheidungen gehen auf dieselbe Voraussetzung zurück: Enthält der Originaltext mindestens ein Zeichen?

Der erste ternäre Ausdruck erzeugt bei leerem Originaltext eine leere Zeichenkette. Der zweite prüft dieses Zwischenergebnis erneut. Die Information über den Sonderfall wandert dadurch vom Eingangswert in die Variable quote.

Das funktioniert. Die Regel „Ohne Originaltext genügt die Antwort“ ist allerdings auf zwei Ausdrücke verteilt.

Mechanik

Eine Guard Clause behandelt den Sonderfall am Anfang. Durch das Early Return, die frühe Rückgabe, ist dieser Pfad anschließend abgeschlossen.

export class ReplyDraftBodyRenderer {
    render(response: ReplyBody, original: OriginalBody): DraftBody {
        const responseText = response.toString();
        const originalText = original.toString();

        if (!originalText) {
            return DraftBody.create(responseText);
        }

        const quote = originalText
            .split("\n")
            .map(line => `> ${line}`)
            .join("\n");

        return DraftBody.create(`${responseText}\n\n${quote}`);
    }
}

Nach dem if steht fest: Der Originaltext ist nicht leer. Der folgende Code kann ihn zitieren und an die Antwort anhängen, ohne nochmals zwischen beiden Fällen zu unterscheiden.

Die Methode hat mehr Zeilen. Dafür lässt sich jeder Pfad unmittelbar lesen: Bei leerem Originaltext wird die Antwort zurückgegeben. Im anderen Fall wird das Zitat aufgebaut und angehängt.

Dabei bleibt die Behandlung des Textes erhalten: Jede mit \n getrennte Zeile bekommt ein zusätzliches > . Aus einer bereits zitierten Zeile > vorher wird > > vorher. Auch Leerzeilen innerhalb eines vorhandenen Textes erhalten das Präfix. Ein Text nur aus Leerzeichen gilt weiterhin als Inhalt; ein zusätzliches trim() würde diese Regel ändern.

Der Vergleich setzt voraus, dass die toString()-Methoden reine String-Darstellungen liefern. Die neue Fassung liest die Antwort vor dem Original; im Ausgangscode ist die Reihenfolge umgekehrt. Bei Seiteneffekten wäre diese Umstellung gesondert zu prüfen.

Würde eine API wie Java Optional helfen?

Das Objekt original ist im gezeigten Vertrag vorhanden. Sein Text darf leer sein. Eine API nach dem Vorbild von Java Optional würde hier eine weitere Abstraktion einführen, um diesen leeren String gesondert zu behandeln.

Für diese lokale Entscheidung reicht der direkte if. Eine zusätzliche Abstraktion hätte dann einen Nutzen, wenn sie einen wiederkehrenden fachlichen Vertrag ausdrückt. Allein das Vermeiden eines if liefert dafür wenig Begründung.

Gegenargument

Für eine einfache Auswahl zwischen zwei Werten ist der ternäre Operator oft gut lesbar:

const label = isExpanded ? "Zuklappen" : "Aufklappen";

Auch mehrere Rückgabestellen helfen nicht automatisch. In einer langen Methode mit vielen verstreuten Abbrüchen kann der Ablauf schwer zu überblicken sein.

Im Renderer ist die frühe Rückgabe nützlich, weil sie einen vollständigen Fall abschließt. Danach bleibt ein zusammenhängender Zitierpfad. Das ist der konkrete Gewinn dieses Umbaus.

Handlungsvorschlag

Wenn mehrere Bedingungen denselben Sonderfall behandeln, prüfe zuerst: Macht dieser Fall die restliche Verarbeitung überflüssig? Dann schließe ihn früh mit einer Guard Clause ab.

Lies anschließend den verbleibenden Ablauf von oben nach unten. Jede weitere Bedingung sollte eine eigene Entscheidung treffen müssen. Im Renderer braucht das Anhängen des Zitats keine zweite Prüfung mehr.

Agentenregel

Die folgende Regel lässt sich direkt in eine AGENTS.md übernehmen. Sie beschreibt, wann ein Agent den Ablauf prüfen soll, wie er ihn vereinfachen kann und welches Verhalten erhalten bleiben muss.

## Sonderfälle früh abschließen

Wenn ein Sonderfall die weitere Verarbeitung überflüssig macht,
bevorzuge eine Guard Clause mit früher Rückgabe. Der verbleibende
Ablauf soll ohne erneute Prüfung desselben Falls von oben nach
unten lesbar sein.

Prüfe besonders auf mehrere bedingte Ausdrücke, die denselben Fall
direkt oder über Zwischenergebnisse behandeln. Führe diese
Entscheidung nach Möglichkeit an einer Stelle zusammen.

Verwende ternäre Operatoren für einfache, lokal verständliche
Wertauswahlen. Führe zusätzliche Abstraktionen nur ein, wenn sie
einen klaren fachlichen oder technischen Nutzen haben.

Bewahre beim Umbau das Verhalten, einschließlich relevanter
Auswertungsreihenfolgen und Seiteneffekte.

Die Regel gibt dem Agenten ein Entscheidungskriterium: Ein Fall soll vollständig abgeschlossen werden können. Die bloße Anzahl ternärer Operatoren oder Rückgabestellen sagt darüber wenig aus.

Prüffrage

Ist nach der frühen Rückgabe klar, welche Voraussetzung für alle folgenden Schritte gilt?

Hier lautet sie: Der Originaltext enthält mindestens ein Zeichen und wird als Zitat angehängt.

Signal

Ein gutes Zeichen: Im Review lässt sich der leere Fall direkt am if erklären. Für den Zitierpfad muss niemand mehr zum ersten ternären Ausdruck zurückspringen, um zu verstehen, warum quote leer sein könnte.

Wenn nach der Guard Clause derselbe Sonderfall erneut geprüft wird, ist die Vereinfachung noch nicht vollständig.
